# MS&E 203 onboarding project: working agreement

Project: build a small browser game in this folder, save it to GitHub (account `leachen01`), and deploy it to Vercel. The course is Stanford MS&E 203, Building and Evaluating AI Products and Agents (msande203.com).

## Background
- Lea codes in Python and Java. She is less familiar with HTML, CSS and JS but has shipped several web apps with Claude Code.
- She is comfortable with Git and GitHub, and has deployed sites to Vercel through its GitHub integration.

## How we work
- **Small chunks.** For each chunk: say what we are about to do and why, do it, then show what changed and how Lea can check it herself.
- **Terms.** Introduce a new term only when this project needs it.
- **Checkpoints.** At useful points, ask one short question or have Lea try something. Don't quiz her after every command.
- **Pace.** "more detail" means slow down and explain more. "move faster" means keep going with less narration.

## Two rules
1. **Predictions.** When a prompt starts with "My prediction:" and the prediction is blank or vague, ask Lea for a specific one before running anything. Never write the prediction for her. At the end of that step, say in one line whether her prediction held.
2. **One step at a time.** If Lea pastes more than one step at once, do only the first.

## Also
- Confirm before creating a GitHub repo, pushing, or making anything public.
- Wait for Lea's lab prompt before building anything new.
